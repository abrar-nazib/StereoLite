\chapter{System Development and Implementation}
\label{ch:implementation}

\section{Introduction}
Chapter \ref{ch:design} fixed the architecture of StereoLite and the
evidence behind every design choice, from the truncated-backbone
encoder through the fail-soft geometry gate. This chapter covers how
that architecture became a trained, optimized, and deployable system.
We describe the software stack and codebase that trains and evaluates
the network, the concrete parameter values the design settled on, the
optimization pass that brought the inference graph inside the edge
latency budget, the compute and sensing hardware the project used, and
the principle of operation that turns a rectified image pair into a
disparity map and, optionally, a metric point cloud.

The chapter is organized around what was built rather than what was
measured. Software Development covers the training and evaluation
codebase and the cloud infrastructure behind it. Network Implementation
gives the exact hyperparameters chosen for the production model.
Optimization and Configuration Selection describes the six changes that
cut inference latency and the further changes required for eight-bit
deployment. Training Objective and Protocol fixes what the network
minimizes during training and the crop, augmentation, and optimizer
protocol applied on top of the training corpus. Hardware and Embedded
Deployment lists the compute and sensing apparatus, including the
Jetson Orin Nano deployment target and the physical stereo rig.
Principle of Operation walks through the
forward pass end to end; this chapter is concerned only with how the
system was built.

\FloatBarrier
\section{Software Development}
\label{sec:software_development}
The network is implemented in PyTorch 2.11 with CUDA 12.8 on Python
3.10. We organized the codebase around scripted drivers rather than
notebooks: a separate script trains the production model, separate
harnesses run the encoder, refinement, and loss ablations under a
matched protocol, and separate drivers run the SceneFlow held-out
evaluation and the zero-shot Middlebury 2014 cross-domain evaluation.
Each driver writes its full configuration and its metrics to a metadata
file next to its outputs, so a reported number can be traced back to
the exact run that produced it.

Two cloud platforms carry the compute load. Full-data training and the
production run described in Section \ref{sec:network_implementation}
ran on Modal-orchestrated cloud A100 jobs, while ablations and
cross-domain evaluations ran on cloud T4 instances, which are cheap
enough to run after every design change without straining the project
budget. An earlier development pass on the edge-tier chassis used a
self-contained Kaggle notebook with data-parallel training across two
T4 GPUs; the production run reported in this thesis moved to the
single-A100 Modal path once the architecture and loss were fixed, since
a single larger GPU trains the full SceneFlow corpus faster than two
smaller ones split across processes. Keeping training, ablation, and
evaluation as separate scripted drivers, each logging its own metadata,
is what let every reported number trace back to a specific run rather
than to a notebook cell that may since have changed.

\FloatBarrier
\section{Network Implementation}
\label{sec:network_implementation}
The design chapter argued for each architectural family; this section
records the exact values the production model uses. The backbone is a
YOLO26s encoder truncated after its first seven blocks. The recurrent
hidden state carries 32 channels, and the refinement head that reads it
carries 48. The tile initialization module builds its correlation
volume from eight groups over 24 disparity hypotheses at one sixteenth
resolution, and the per-iteration local correlation looks up a
half-range of two pixels around the current disparity estimate. The
refinement schedule runs two iterations at one sixteenth resolution,
three at one eighth, and three at one quarter, and the geometry
encoding volume is narrowed to a band of plus or minus 16 disparities
around the tile estimate rather than spanning the full disparity range.
Table \ref{tab:arch_config} of Appendix~\ref{app:specs} gives the complete
configuration record of the trained checkpoint, verbatim, alongside
these headline values.

Table \ref{tab:train_config} lists the training-side configuration that
Chapter \ref{ch:design} selected and justified: the optimizer, schedule,
batch size, input protocol, augmentation set, training data, validation
protocol, and training hardware. Every value in the table is the result
of a controlled ablation, and the design-evidence audit of
Chapter \ref{ch:design} traces each choice to its justification.
Section \ref{sec:training_objective} below fixes the
training objective and the protocol narrative behind this table in
full.

\section{Optimization and Configuration Selection}
\label{sec:optimization}
Reaching the latency target required optimizing the network's
inference graph, not just training it. We applied six changes: we
rewrote the cost-volume construction loops to use padded zero-copy
views instead of allocating and zeroing a feature map for every
disparity bin; we reduced the grid-sample calls from 48 to eight by
batching the lookups and caching the sampling grids; we hoisted the
static channels of the recurrent input, which are re-convolved every
iteration, to run once per scale, following the precomputed-context
trick of RAFT-Stereo \cite{lipson2021raftstereo}; we fused the gate
convolutions and the four output heads, which share inputs; we removed
dead inference-path code; and we narrowed the geometry volume to a band
around the tile disparity. We proved each change equivalent before
adopting it, either bitwise or through a matched A/B comparison, and
together they cut the full-precision latency by a factor of 1.74.

Figure \ref{fig:export_pipeline} lays the deployment path out: the four
graph optimizations act on the full-precision model before export,
while the three operator swaps prepare the graph for eight-bit
calibration.

\begin{figure}[!htbp]
\centering
\includegraphics[width=\textwidth]{fig_4_5_export_preview}
\caption{Export pipeline from trained checkpoint to INT8 TensorRT engine.}
\label{fig:export_pipeline}
\end{figure}

The same pass also had to clear three operators that block eight-bit
deployment: the unfold operation in convex upsampling, group
normalization on some accelerator toolchains, and three-dimensional
convolution on neural processing units. We swapped each for a
quantization-friendly equivalent, then exported and calibrated the
resulting graph to an eight-bit TensorRT engine for the Jetson Orin
Nano. Table \ref{tab:efficiency_findings} summarizes the six changes and
their equivalence status.

\section{Training Objective and Protocol}
\label{sec:training_objective}
The optimizations above act on a network that already has to be trained
correctly in the first place. This section fixes what the network
minimizes during training and the data protocol under which that
objective is applied, the two pieces of the design methodology that sit
upstream of the parameter values already listed in Table
\ref{tab:train_config}.

\subsection{Training Objective}
The network trains under the multi-scale objective of \eqref{eq:loss}. A
pixel counts as valid when its ground-truth disparity is finite and lies
between 0 and 320 pixels. Each lower-scale prediction is resized to full
resolution and multiplied by its scale factor before comparison. The
objective weights an L1 term at every scale, heaviest at full
resolution, adds a matching L1 term on the geometry-volume output, and
augments the full-resolution prediction with a Sobel
gradient-consistency term, a threshold hinge stack, a KITTI-style
D1-relative hinge \cite{menze2015kitti}, an edge-aware smoothness term, and a gated
slant-supervision term that trains the plane slopes only where they are
trustworthy. The slant term pairs with plane rendering: it makes the
slopes accurate enough for the rendering step to sharpen boundaries.

We chose this composition by ablation rather than guesswork. The loss
study tested nine formulations: plain L1
under-serves the outlier metrics, hinge terms on a single threshold
overfit that threshold, and the threshold stack combined with the D1
hinge was the only formulation to win both the end-point error and the
outlier rates. The production objective descends from that winner,
keeping the gradient term for its sub-pixel benefit and holding the
smoothness term to a small weight so it regularizes without blurring.

\begin{equation}
\begin{aligned}
\mathcal{L} \;=\;& 1.00\,\mathcal{L}_{1}(d_{\mathrm{full}})
 + 0.50\,\mathcal{L}_{1}(d_{1/2})
 + 0.30\,\mathcal{L}_{1}(d_{1/4})
 + 0.20\,\mathcal{L}_{1}(d_{1/8})
 + 0.10\,\mathcal{L}_{1}(d_{1/16})\\
&+ 0.15\,\mathcal{L}_{1}(d_{\mathrm{gev}})
 + 0.50\,\mathcal{L}_{\mathrm{grad}}
 + 0.20\,\mathcal{L}_{\mathrm{thr}}
 + 0.20\,\mathcal{L}_{\mathrm{D1}}
 + 0.02\,\mathcal{L}_{\mathrm{smooth}}
 + 0.30\,\mathcal{L}_{\mathrm{slant}}
\end{aligned}
\label{eq:loss}
\end{equation}
where $\mathcal{L}_1$ is the masked mean absolute disparity error,
$\mathcal{L}_{\mathrm{grad}}$ a Sobel gradient-consistency term,
$\mathcal{L}_{\mathrm{thr}}$ a hinge over the error thresholds
$\{0.5, 1, 2, 3\}$ pixels, $\mathcal{L}_{\mathrm{D1}}$ the D1-relative
hinge, $\mathcal{L}_{\mathrm{smooth}}$ an edge-aware smoothness term, and
$\mathcal{L}_{\mathrm{slant}}$ the gated slant supervision.

\caption{Six disparity scales supervised with L1, gradient consistency, and threshold terms.}

\subsection{Datasets and Training Protocol}
This subsection fixes the protocol applied on top of the SceneFlow
finalpass corpus, the thesis's training and in-domain test set. Training
samples
random 384 by 640 windows, co-located in both views, from the native 960
by 540 frames, which preserves native disparity magnitudes rather than
shrinking them; this native-crop protocol substantially outperforms the
legacy protocol of downscaling the whole frame before cropping. Three
augmentations from the OpenStereo recipe
apply during training: asymmetric color jitter, right-image-only random
erasing, and random scaling. Optimization uses AdamW with a OneCycle
schedule over 60,000 steps at a peak learning rate of $8 \times 10^{-4}$,
a batch of 32, and bfloat16 mixed precision, on a single A100 GPU. Input
is normalized to the unit interval at the model boundary. Validation
uses a fixed 400-pair subset of the test set at the native 960 by 540
axis, evaluated every thousand steps, with a resized-axis measurement
logged alongside for comparison against work that reports at the resized
scale. Table \ref{tab:train_config} lists this configuration in full.

\section{Hardware and Embedded Deployment}
\label{sec:hw_deployment}
The apparatus divides into compute and sensing. On the compute side,
training runs on a single cloud A100 GPU with 80 gigabytes of memory.
Ablations and evaluations run on a cloud T4, chosen for its low cost,
which keeps a controlled study practical after every design change. The
local latency benchmark runs on an RTX 3050 laptop GPU with roughly 4
gigabytes of memory, representing the low end of the deployment memory
budget. The intended deployment target is the Jetson Orin Nano class of
edge accelerator, on which we measured the optimized eight-bit model
directly.

On the sensing side, real-camera pairs come from a calibrated low-cost
binocular rig that streams a 2560 by 720 side-by-side image, split into
a rectified 1280 by 720 pair per frame. This rig supplies the real-data
qualification of the trained model: the zero-shot qualitative pairs, the
real-camera agreement protocol, and the three-dimensional
reconstructions it supports. Housing both
the training-side compute and the sensing-side rig in the same section
keeps the apparatus that produced every downstream number in one place,
ahead of the experimental protocols built on top of it.

\section{Principle of Operation}
\label{sec:principle_of_operation}
In deployment the system runs as a fixed feed-forward pipeline. A
rectified left and right pair enters at the inference resolution of 384
by 640 pixels, normalized to the unit interval, and passes through the
blocks fixed in Chapter \ref{ch:design}. The shared encoder processes
both views in a single batched pass and emits matching features at one
quarter, one eighth, and one sixteenth resolution, while a separate
context encoder reads the left image alone and produces the context
maps that feed the recurrent state.

Matching begins at the coarsest scale. The tile initialization module
builds the group-wise correlation volume of \eqref{eq:gwc} at one
sixteenth resolution, regularizes it with a small three-dimensional
network, and reads off the initial disparity and confidence through the
soft-argmax of \eqref{eq:softargmax_init}; the plane slopes start at
zero, and the hidden state starts from the coarsest context map. The
recurrent refinement then runs its fixed schedule: two iterations at
one sixteenth, three at one eighth, and three at one quarter resolution.
At each iteration the right features are warped by the current
disparity, a local correlation is evaluated over five offsets, and the
convolutional gated recurrent unit of \eqref{eq:convgru} updates the
hidden state; gated residuals adjust the disparity, the plane slopes,
and the confidence. Between scales, the plane-aware propagation of
\eqref{eq:plane_prop} carries the tile state to the finer grid along its
local slanted-surface hypothesis rather than by plain interpolation.

At one quarter resolution, the narrow-band geometry encoding volume
produces its independent proposal per \eqref{eq:gev_expect}, and the
fail-soft gate of \eqref{eq:failsoft} blends that proposal into the
recurrent estimate only where the learned weight favors it. This
corrects regions the tile state resolved poorly, without disturbing the
ones it resolved well. The refined quarter-resolution state is rendered
from its tile planes with an edge gate and upsampled to full resolution
by two learned convex-combination stages, each output subpixel a
softmax-weighted mixture of its three-by-three coarse neighborhood. The
result is a dense full-resolution disparity map.

Disparity becomes depth through the calibrated relations of
\eqref{eq:backprojection}: depth follows $Z = fB/d$, and each valid
pixel optionally back-projects to a metric three-dimensional point in
the camera frame, colored by its left-image pixel. On the project's
rig, the calibrated focal length and baseline scale to the inference
resolution by the width ratio, so the point cloud is metric without
further tuning. This single forward pass, from image pair to disparity
map and optional colored point cloud, is the operation this thesis
measures throughout.

\section{Summary}
This chapter traced the path from the network architecture to a
trained, deployable system. The codebase separates training, ablation,
and evaluation into scripted drivers that each log their own
configuration and metrics, running on Modal-orchestrated cloud A100 and
T4 GPUs. The production model fixes a truncated YOLO26s backbone, a
32-channel recurrent state, an eight-group correlation volume, and a
two, three, three iteration schedule, and this configuration is
recorded in full. A six-change, equivalence-proven optimization pass
cut inference latency by a factor of 1.74 and cleared the operators
that block eight-bit deployment, producing a calibrated TensorRT engine
for the Jetson Orin Nano. Training itself runs under an eleven-term
multi-scale objective built around a threshold-stack and D1-relative
hinge, applied to random native-resolution crops of the SceneFlow
corpus with a three-part augmentation recipe and a sixty-thousand-step
OneCycle schedule. The compute and sensing apparatus spans a cloud A100
for training, a cloud T4 for ablations, an RTX 3050 for local latency
benchmarking, the Jetson Orin Nano deployment target, and a calibrated
low-cost stereo rig for real-camera qualification. The principle of
operation section walked through the resulting forward pass, from a
rectified image pair to a full-resolution disparity map and an optional
metric point cloud.
